📌 RESPOSTA RÁPIDA (1 minuto)
════════════════════════════════════════════════════════════════════════════════════

Quando o ESP32 reinicia, a sequência é:

  1. ✓ Setup: Testar PCF8574 entrada/saída, RTC, Carregar NVS
  2. ✓ Ler: Estado físico do motor via PCF8574
  3. ✓ Comparar: NVS (estado anterior) vs Físico (estado atual)
     • Se IGUAL → Nenhum pulso
     • Se DIFERENTE → Enfileirar pulso
  4. ✓ Validar: Modo LOCAL/MANUAL/AGENDA
  5. ✓ Executar: Máquina de estados do pulso
     • PULSE_VALIDATING (2500ms) → Verificar I2C, enviar ao PCF
     • PULSE_ACTIVE (1000ms) → Manter pulso ligado
     • IDLE → Pronto para próximo

TOTAL: ~15-30 segundos do boot até operação normal


🎯 FLUXO SIMPLIFICADO (3 minutos)
════════════════════════════════════════════════════════════════════════════════════

Boot
  ↓
Inicializar Hardware (setup)
  ├─ PCF8574 entrada OK?
  ├─ PCF8574 saída OK?
  ├─ RTC OK?
  └─ Carregar NVS (ultimoComandoMotorOff, modo, etc.)
  ↓
Ler Estado Físico (TaskIOControl - 1ª execução)
  ├─ Wire.requestFrom(0x20, 1)  ← PCF entrada
  ├─ Decodificar bits
  │  ├─ IN1 (Bit 0) = Motor Status (true=DESLIGADO, false=LIGADO)
  │  └─ IN2 (Bit 1) = Modo (true=LOCAL, false=APP)
  └─ motorInputsInitialized = true
  ↓
Verificar Reconciliação (apenas 1ª vez)
  ├─ Está em LOCAL?
  │  └─ SIM → Parar aqui, nenhum pulso
  ├─ Está em MANUAL APP?
  │  ├─ SIM → Comparar NVS vs Físico
  │  │        Se divergentes → requestPulse()
  │  └─ NÃO (AGENDA) → Validar RTC + horário
  └─ startupMotorReconcilePending = false
  ↓
Processar Pulso (máquina de estados)
  ├─ Estado 1: PULSE_VALIDATING (timeout 2500ms)
  │  ├─ Aguardar 2000ms (estabilização)
  │  ├─ Verificar I2C (Wire.requestFrom(0x68, 1))
  │  │  └─ Se falhar → Pulso ABORTADO
  │  ├─ Validar Modo (se APP)
  │  │  └─ Se não for MANUAL → Pulso cancelado
  │  ├─ Enviar pulso ao PCF (output_PLC &= ~(1 << bit))
  │  │  └─ Se falhar → Pulso ABORTADO
  │  └─ Salvar em NVS (apenas APP em MANUAL)
  │     └─ Se falhar → Log de erro (pulso já foi)
  │
  ├─ Estado 2: PULSE_ACTIVE (1000ms)
  │  ├─ Bit permanece em 0 (ligado no PCF)
  │  ├─ Circuito detecta e aciona relé
  │  └─ Motor inicia
  │
  └─ Estado 3: IDLE
     ├─ Retirar pulso (output_PLC |= (1 << bit))
     ├─ Voltar a IDLE
     └─ Próximo pulso (se pendente)
  ↓
Aguardar Confirmação de Feedback
  ├─ Monitorar próximas leituras do PCF
  └─ Se estado == esperado → Inicialização completa
  ↓
Operação Normal (ciclos de 50ms)
  ├─ Leitura de sensor de nível
  ├─ Processamento de comandos APP
  ├─ Verificação de agenda (se ativo)
  └─ Atualizar display/Blynk


⏱️ PRAZOS CRÍTICOS
════════════════════════════════════════════════════════════════════════════════════

Setup hardware:              ~5 segundos
Leitura PCF8574:             200ms (timeout)
Esperar estabilização I2C:   2000ms
Pulso enviado ao PCF:        ~50ms
Pulso permanecer ativo:      1000ms
Salvar NVS:                  ~100ms
Confirmação de feedback:     200-500ms

TOTAL (boot até "motor ativo"): 15-30 segundos


🛡️ 5 VERIFICAÇÕES DE SEGURANÇA
════════════════════════════════════════════════════════════════════════════════════

1. BARRAMENTO I2C OK
   ├─ Wire.requestFrom(0x68, 1) > 0  ✓
   └─ Se falhar → Pulso ABORTADO

2. MODO VALIDADO (se APP)
   ├─ !gInputs.modoLocal && remotoOuAgenda == 0  ✓
   └─ Se falhar → Pulso CANCELADO

3. PCF8574 RESPONDE
   ├─ writeOutputPLC() OK  ✓
   └─ Se falhar → Bit restaurado, pulso ABORTADO

4. NVS ESCREVE (se APP)
   ├─ preferences.putBool(...) > 0  ✓
   └─ Se falhar → Log de erro (pulso já foi enviado)

5. FILA LIMITADA
   ├─ Máximo 2 pulsos (1 ativo + 1 pendente)
   └─ Terceiro → REJEITADO


📋 3 MODOS DE OPERAÇÃO
════════════════════════════════════════════════════════════════════════════════════

🏠 LOCAL (gInputs.modoLocal == true)
   ├─ Motor controlado por botões do painel
   ├─ NÃO há restauração remota
   └─ Sistema apenas monitora

📱 MANUAL APP (gSchedule.remotoOuAgenda == 0)
   ├─ Pulsos enviados por comando Blynk
   ├─ Estado salvo em NVS
   ├─ Restaurado no boot se divergente
   └─ Exemplo: Usuario clica "LIGAR" → Salva em NVS

📅 AGENDA (gSchedule.remotoOuAgenda == 1)
   ├─ Pulsos enviados por horário programado
   ├─ Estado NÃO é salvo em NVS
   ├─ RTC deve estar operacional
   └─ Exemplo: Ligar 06:00, desligar 18:00


🚨 SITUAÇÕES DE FALHA (O que aborta o pulso)
════════════════════════════════════════════════════════════════════════════════════

| Falha | Verificação | Resultado |
|-------|-------------|-----------|
| I2C Travado | Wire.available() == 0 | Pulso ABORTADO ❌ |
| Timeout | 2500ms excedido | Pulso ABORTADO ❌ |
| PCF desconectado | writeOutputPLC() falha | Pulso ABORTADO ❌ |
| Modo inválido | APP em LOCAL/AGENDA | Pulso CANCELADO ⚠️ |
| Fila cheia | pendingType != NONE | Pulso REJEITADO ⚠️ |
| NVS falha | preferences.putBool() == 0 | Pulso enviado, não salvo ⚠️ |

📞 PRINCIPAIS PONTOS (Para lembrar)
════════════════════════════════════════════════════════════════════════════════════

✓ NVS é salvo APENAS em modo MANUAL APP
  (Não em LOCAL, não em AGENDA)

✓ Máquina de estados tem 3 fases:
  VALIDATING (2500ms) → ACTIVE (1000ms) → IDLE

✓ Verificação I2C é essencial:
  Se barramento travado → Pulso é abortado

✓ Fila de pulsos é limitada:
  Máximo 2 (1 em execução + 1 pendente)

✓ Modo LOCAL:
  Nenhum pulso de restauração é enviado
