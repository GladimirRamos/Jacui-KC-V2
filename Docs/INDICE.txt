💡 COMO RASTREAR UM PROBLEMA
════════════════════════════════════════════════════════════════════════════════════

1. SINTOMA: Motor não inicia no boot
   
   a) Verificar logs:
      "PCF8574 entrada OK?" → Se não, hardware falhou
      "BARRAMENTO TRAVADO?" → Se sim, I2C está ruim
      "Pulso LIGAR solicitado?" → Se não, reconciliação não disparou
   
   b) Verificar modo:
      Painel em LOCAL? → Motor não será comandado remotamente
      NVS com estado anterior? → Comparar com físico
      RTC funcionando (se AGENDA)? → Validar horário
   
   c) Usar CENARIOS_PRATICOS.md:
      Qual cenário se aplica? → Ver sequência esperada

2. SINTOMA: Pulso enviado mas motor não responde
   
   a) Verificar logs:
      "Pulso LIGAR finalizado com sucesso?" → Pulso foi enviado
      "Estado do motor confirmado?" → Feedback foi recebido?
   
   b) Verificar hardware:
      Relés de comando funcionando? → Teste com jumper
      Contactora recebendo sinal? → Medir com voltímetro
   
   c) Usar CENARIOS_PRATICOS.md → Cenário 2

3. SINTOMA: Pulsos aparecem na fila
   
   a) Verificar timeout:
      PULSE_VALIDATING durando > 2500ms? → I2C problema
   
   b) Usar CENARIOS_PRATICOS.md → Cenário 6
   
   c) Implementar retry se necessário

4. SINTOMA: NVS não atualiza
   
   a) Verificar logs:
      "Falha ao salvar comando"? → Flash corrompida
      "Falha ao abrir NVS"? → Namespace erro
   
   b) Usar CENARIOS_PRATICOS.md → Cenário 7
   
   c) Poder ser um problema raro (memória cheia)
